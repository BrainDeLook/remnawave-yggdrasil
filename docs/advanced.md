# Техническая справка

[← Вернуться к инструкции установки](../README.md)

Эта страница нужна для автоматизации, нестандартной VPS и ручной работы с JSON. Для обычной установки достаточно мастера из README.

## Изменения в панели и резервные копии

Мастер дополняет существующий профиль, активирует выбранные inbound на выбранной ноде и создаёт для них Host. У новых Host настраивается доступ выбранных сквадов; без их выбора новый Host создаётся выключенным.

Исходные inbound и DNS сохраняются. В правила `routing.rules`, адресованные исходному TCP через `inboundTag`, добавляются теги новых inbound. Существующие дополнения сохраняют свои индивидуальные правила. В новые gRPC/XHTTP не переносится flow Vision; параметры Reality (`dest`/`target`, `xver`, ключи и SNI) берутся из исходного inbound.

Перед изменением мастер проверяет, что нода не перешла на другой профиль и JSON профиля не изменился. Полностью исключить одновременную запись другого администратора API не позволяет.

Настройки находятся в `/etc/remnawave-yggdrasil/`, программа — в `/opt/remnawave-yggdrasil/`. Резервные JSON профиля и планы сохраняются в `/etc/remnawave-yggdrasil/backups/`, доступном только root. API-токен и секретная ссылка туда не записываются.

## Yggdrasil на VPS

При выборе Yggdrasil устанавливается официальный пакет **0.5.14** для amd64/arm64 с проверкой SHA256. У существующего Yggdrasil 0.5.x сохраняются идентичность и настройки; активный конфиг определяется через systemd. Автоматический переход с другой ветки не выполняется.

IPv6 включается только на loopback и TUN Yggdrasil. WAN, default route и DNS не перенастраиваются. При повторной настройке Yggdrasil перезапускается.

## Сеть и firewall

Yggdrasil inbound слушает IPv6 wildcard на выделенном TCP-порту, обычно **1488**, чтобы Xray мог запуститься до готовности TUN. Собственная таблица nftables закрывает этот порт на остальных внешних адресах и разрешает вход на IPv6 Yggdrasil согласно выбранному режиму. Локальный loopback разрешён отдельно.

Правила SSH применяются отдельно на адресе Yggdrasil; учитываются выбранный порт и обнаруженные порты OpenSSH. Публичный SSH не перенастраивается. Загрузка Yggdrasil зависит от успешного запуска службы доступа.

Публичные gRPC/XHTTP/Hysteria2 открываются точечно в активном UFW. UFW автоматически не включается; у активного UFW должна работать поддержка IPv6. Docker Compose и Docker NAT/FORWARD не переписываются.

При нестандартном INPUT firewall мастер может отказаться от автоматического применения. Подготовьте точечные разрешения самостоятельно и используйте `--firewall-ready`. Этот флаг подтверждает готовность правил, но не настраивает сторонний firewall.

При обнаружении таблицы `ygg_vless_access` от отдельного установщика `ygg-vless` установка останавливается: его правила могут запрещать остальные Yggdrasil-порты. Нужна отдельная согласованная миграция правил. Глобальный сброс firewall для этого не требуется.

## Сертификаты Hysteria2

### Новый inbound

Мастер ищет сертификат в `/etc/letsencrypt/live/*/fullchain.pem` по содержимому и домену Host. Поддерживаются wildcard и папки с суффиксом `-0001`: имя папки не обязано совпадать с доменом. Из подходящих выбирается действующий сертификат с наибольшим оставшимся сроком.

Проверяются срок действия, домен и соответствие ключа сертификату. Если пара хранится в другом месте, укажите её в мастере или через `--cert`/`--key`. Выпуск нового сертификата не выполняется.

Для нового управляемого Hysteria2 нужны общий доступный для записи `/dev/shm:/dev/shm` и root внутри контейнера. Используются отдельные файлы:

```text
/dev/shm/remna-ygg-hy2-cert.pem
/dev/shm/remna-ygg-hy2-key.pem
```

Ключ получает права `600`. Таймер восстанавливает файлы после загрузки и проверяет обновления раз в час. Контейнер Remnanode перезапускается только при изменении файлов; это кратко прерывает все протоколы локальной ноды.

### Существующий inbound

У стороннего Hysteria2 проверяется реальная пара из настроек и mounts контейнера, включая нестандартные пути и mounts только для чтения. Прежнее обновление сохраняется, чужие файлы не перезаписываются. В этом сценарии `--cert`/`--key` не подменяют сертификат.

У нашего Hysteria2 повторный запуск сохраняет прежний источник, если новый не указан явно. Старые общие имена `/dev/shm/hysteria_*.pem` переводятся на отдельные файлы только в профиле без соседних нод. В общем профиле пути сохраняются ради совместимости.

Cron-задачи сторонних скриптов не удаляются. Если ранее был настроен ежедневный перезапуск ноды, он продолжится.

## Автоматический запуск

Параметры передаются после `bash /tmp/remna-ygg-install.sh`. Флаг `--yes` заранее разрешает применение без финального вопроса. Без него работает обычный мастер.

| Параметр | Назначение |
|---|---|
| `--panel URL` | Корневой адрес панели |
| `--node UUID` | Нода этой VPS |
| `--source-host UUID` | Исходный рабочий TCP Reality Host |
| `--name 'Название'` | Общее название без протокола |
| `--protocol hy2\|grpc\|xhttp\|ygg` | Дополнение; можно повторять флаг |
| `--squad UUID` | Сквад для всех дополнений текущего запуска; можно повторять |
| `--access-mode subscription` | Yggdrasil по подписке, без VPN-списка IP |
| `--access-mode restricted` | Yggdrasil по подписке и списку IP |
| `--allow-ip IPv6_или_подсеть` | Разрешённый источник VPN; можно повторять |
| `--ssh` / `--no-ssh` | Включить или выключить SSH через Yggdrasil |
| `--ssh-allow-ip IPv6_или_подсеть` | Отдельный источник SSH; можно повторять |
| `--ssh-port PORT` | Порт SSH через Yggdrasil |
| `--ygg-port PORT` | Порт создаваемого Yggdrasil inbound, по умолчанию 1488 |
| `--cert PATH`, `--key PATH` | Источник сертификата и ключа управляемого Hysteria2 |
| `--peer URI` | Пиры Yggdrasil; можно повторять, явный список заменяет прежний |
| `--firewall-ready` | Подтверждение готовности нестандартного firewall |
| `--check` | Проверить API и показать план без применения |
| `--result` | Показать сохранённый результат |
| `--plain` | Использовать прежний текстовый мастер вместо экранного меню |

При `--yes` нода и Host должны определяться однозначно. Укажите явные UUID, если вариантов несколько.

`--allow-ip` подразумевает `restricted`; сочетание с `--access-mode subscription` отклоняется. VPN-список требует и адрес `200:…` без `/7`, и LAN-префикс `300:…/64`.

При `subscription` флаг `--ssh` требует отдельный `--ssh-allow-ip` либо сохранённый SSH-список. Ограничения старого подключения 0.1.x на прежнем порту сохраняются независимо.

### Передача секретов

| Значение | Файл | Переменная окружения |
|---|---|---|
| API-токен | `--token-file PATH` | `REMNAWAVE_API_TOKEN` |
| Ссылка/Cookie защиты панели | `--access-file PATH` | `REMNAWAVE_PANEL_ACCESS` |

Файлам нужен режим `600`. Сам токен или ссылка не принимаются значением аргумента командной строки и не сохраняются установщиком. Для TinyAuth/Cloudflare Access нужен предусмотренный этими средствами доступ к API; токен Remnawave не заменяет внешнюю авторизацию.

### Цвет терминала

Цвет отключается при наличии `NO_COLOR`, при `TERM=dumb` и перенаправлении вывода в файл/канал:

```bash
NO_COLOR=1 bash /tmp/remna-ygg-install.sh
```

`NO_COLOR` убирает цвета, но сохраняет экранное меню. Для отключения самого меню используйте `--plain`. Меню автоматически включается только в интерактивном терминале с поддерживаемым `TERM`; обычный Linux Python предоставляет модуль `curses`, отдельные Python-пакеты для интерфейса не нужны.

При возврате Esc мастер повторяет только подготовительные чтения и восстанавливает ранее введённые ответы. Объекты меню сохраняются по UUID, поэтому изменение порядка нод/сквадов в ответе API не подменяет выбор. Изменение раннего ответа сбрасывает зависимые последующие ответы. После подтверждения применение не повторяется навигацией назад.

## Необязательный локальный конвертер

Для обычной установки он не нужен: профиль настраивает мастер через API. Конвертер оставлен для подготовки JSON вручную, без сайта и отправки конфигурации третьей стороне.

Интерфейс из исходников — `python desktop.py` (нужен Python с Tk). Командная строка:

```bash
python converter.py source.json result.json --base node-vless-443 --protocol ygg
```

Результат сохраняется **в новый файл**. Зависимости VPS, активные inbound, Host и сквады при ручной работе настраиваются отдельно. JSON содержит приватные ключи: его нельзя публиковать.

Для Windows доступен [старый RemnawaveConverter.exe из v0.2.1](https://github.com/BrainDeLook/remnawave-yggdrasil/releases/tag/v0.2.1). Он не включает последующие исправления конвертера. Новые обычные выпуски EXE не содержат; отдельная сборка Windows запускается вручную через workflow.

## Старый режим 0.1.x

Он создавал дополнительный Host на прежнем inbound. При переходе на новый отдельный inbound старый Host автоматически не удаляется. После проверки нового подключения его можно отключить в панели; само скрытие Host не отзывает реквизиты.

[Архивная инструкция 0.1.x](legacy-v0.1.md) описывает старый мастер, включая необязательный Username для личной проверки. В текущем мастере этот Username вводить не нужно.
