# Remnawave + Yggdrasil

[![Проверки](https://github.com/BrainDeLook/remnawave-yggdrasil/actions/workflows/check.yml/badge.svg)](https://github.com/BrainDeLook/remnawave-yggdrasil/actions/workflows/check.yml)

Установщик запускается **на VPS уже работающей Remnanode** и добавляет подключение через Yggdrasil в ту же панель Remnawave. Второй sing-box/Xray для обслуживания клиентов не устанавливается: используются существующий VLESS TCP Reality inbound, UUID пользователей, лимиты и учёт трафика панели.

Первый выпуск поддерживает Remnawave 3.x, Debian 12+/Ubuntu 22.04+, amd64/arm64, systemd и обычный VLESS TCP/RAW Reality. Для Docker стандартный вариант — `network_mode: host`, как у eGames. Нода, установленная вручную, тоже подходит, если её существующий Xray принимает IPv6 на адресе Yggdrasil.

## Что нужно сделать вам

### 1. Подготовить панель

В Remnawave должны уже работать **Node и обычный VLESS Reality Host**, через который подключаются пользователи. Подходят существующие установки eGames и конфигурации с дополнительными протоколами: их профили скрипт не меняет.

Создайте API-токен в разделе API-токенов панели. Для первого запуска проще использовать отдельный временный токен с полным доступом, затем отозвать его. Для ограниченного токена нужны чтение Nodes, Hosts и Config Profiles, создание/обновление Hosts; чтение Users необходимо только для личной ссылки/проверки. Точные названия scopes зависят от версии панели.

Нужны:

- URL **самой панели**, например `https://panel.example.com`, без `/dashboard`, `/api/...` и пути подписки;
- API-токен — вводится скрыто, **не отправляйте его в чат**;
- название Node именно того VPS, где запускается установщик;
- исходный рабочий VLESS TCP Reality Host этой ноды;
- при желании — UUID существующего активного **пользователя панели** для полной HTTPS-проверки и вывода его личной ссылки. Это UUID записи пользователя, не VLESS UUID и не short UUID.

API должен быть доступен с VPS. Если перед панелью TinyAuth/Cloudflare Access или собственная cookie-защита, разрешите API-доступ штатным способом. Установщик не отключает TLS-проверку и не обходит внешний вход. HTTP разрешён только для панели на `localhost`.

### 2. Подготовить адреса доступа

На своём роутере откройте **Сеть → Интерфейсы → Yggdrasil**:

| Поле | Что скопировать | Для чего |
|---|---|---|
| IPv6, например `200:1111:2222:3333:4444:5555:6666:7777/7` | `200:1111:2222:3333:4444:5555:6666:7777` **без `/7`** | Тахион и соединения самого роутера |
| IPv6-PD, например `300:1111:2222:3333::/64` | `300:1111:2222:3333::/64` **вместе с `/64`** | ПК/телефоны за роутером, в том числе при смене их IPv6 внутри подсети |

Это вымышленные примеры. Вводите свои значения. Адрес VPS в список клиентов не добавляйте. В обоих полях можно несколько значений через пробел — своих и друзей. `/64` разрешает всю соответствующую LAN.

SSH опционален: перед адресами будет вопрос «Нужен SSH через Yggdrasil?». У него отдельный список IP/подсетей. Разрешение VLESS не открывает SSH. Для входа по-прежнему нужен существующий аккаунт сервера и его ключ/пароль. Публичный SSH не перенастраивается.

### 3. Запустить на VPS ноды

Подключитесь по публичному IP VPS от root и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/BrainDeLook/remnawave-yggdrasil/main/install.sh -o /tmp/remna-ygg-install.sh && bash /tmp/remna-ygg-install.sh
```

Если curl отсутствует: `apt-get update && apt-get install -y curl ca-certificates`.

Мастер спросит URL и скрытый токен, предложит выбрать ноду/исходный Host, название нового подключения, необходимость SSH и списки разрешённых адресов. Если подходящая нода/Host только одна, она выбирается автоматически; всё равно проверьте напечатанное название и адрес API.

Скрипт проверит API, установит Yggdrasil с проверкой SHA256, дождётся живого пира, проверит существующий IPv6-слушатель Xray, добавит точечные разрешения и создаст **дополнительный Host** с адресом Yggdrasil и прежним портом inbound (обычно 443). SNI останется доменом Reality. Адрес API в карточке Node не меняется.

При указанном UUID пользователя скачивается проверенный вспомогательный Xray **только для короткого теста**. Через его учётную запись выполняется HTTPS-запрос; после теста процесс завершается. Это не второй постоянно работающий proxy core.

### 4. Подключиться

Обновите **существующую личную подписку** в клиенте. Новый Host появится у пользователей, которым доступен исходный inbound и ограничения исходного Host. Скрипт сохраняет его ограничения Internal Squads; каждому пользователю панель выдаёт собственный UUID. Общей ссылки/учётной записи для всех не создаётся.

Если указали UUID пользователя для проверки, в конце будут его личная VLESS-ссылка и JSON Тахиона с `bind_interface: "yggdrasil"`. Они содержат доступ этого пользователя; храните их как пароль. Измените имя интерфейса в JSON, если на роутере оно другое. Обычная VLESS-ссылка локальную привязку интерфейса передать не может.

Yggdrasil должен работать на клиенте или на роутере с IPv6-маршрутизацией LAN. Установка на VPS сама не настраивает домашний роутер.

Повторно вывести результат:

```bash
remnawave-yggdrasil --result
```

Без UUID пользователя выводятся адрес, Host и состояние, но личная ссылка не создаётся; в этом случае установка проверяет TCP-доступность, а не авторизацию VLESS. Локальный HTTPS-тест не заменяет тест с вашего удалённого клиента.

## Обновление и проверка без изменений

Повторите команду установки. Имя Host, адрес/ключ Yggdrasil и разрешения сохраняются. Токен нужно ввести заново: он не хранится. Скрипт обновляет только свой Host, помеченный `YGGDRASIL_NATIVE`, и не создаёт дубликат.

Проверить API и вывести план до установки:

```bash
bash /tmp/remna-ygg-install.sh --check
```

`--check` не устанавливает пакеты рабочего стека и не пишет настройки/Host; при отсутствии Python/curl загрузчик предварительно установит их. Проверка API не доказывает доступность IPv6 Xray и не выполняет HTTPS-тест.

Для автоматизации используйте файл токена с правами `600` либо переменную окружения `REMNAWAVE_API_TOKEN`. Токен аргументом командной строки не принимается. Пример с **вымышленными UUID**:

```bash
chmod 600 /root/remnawave-api.token
bash /tmp/remna-ygg-install.sh --yes \
  --panel https://panel.example.com --token-file /root/remnawave-api.token \
  --node UUID_НОДЫ --source-host UUID_ИСХОДНОГО_HOST --name 'NL · Yggdrasil' \
  --allow-ip 200:1111:2222:3333:4444:5555:6666:7777 \
  --allow-ip 300:1111:2222:3333::/64 --no-ssh \
  --user-uuid UUID_ПОЛЬЗОВАТЕЛЯ
```

С `--yes` обязательны адрес роутера и LAN-подсеть, либо их сохранённая пара. `--ssh` включает SSH, повторяемый `--ssh-allow-ip` задаёт его отдельные разрешения. `--ssh-port` меняет порт; `2222` зарезервирован для API Remnanode. `--peer URI` задаёт собственных пиров, сохраняя идентичность Yggdrasil.

## Границы совместимости

- Профиль Xray, существующие Host, пользователи, Docker Compose, сертификаты, cron, default route и настройки DNS не меняются. Установщик не вызывает скрипты eGames/Rrezzak09VPN, не обновляет Docker и не перезапускает Remnanode.
- Создаваемый Host использует существующий inbound. Это ещё один путь к тому же сервису с общим учётом пользователя; отдельной статистики по двум Host одного inbound не обещается.
- Существующий Xray должен принимать TCP на Yggdrasil IPv6. Если он привязан только к конкретному IPv4 или находится в Docker bridge без IPv6-доступа, установка остановится до создания Host. Профили автоматически не переписываются. Такая конфигурация требует отдельного изменения слушателя/сети ноды.
- IPv6 включается только на TUN-интерфейсе Yggdrasil и loopback. WAN/default sysctl сохраняются, включая отключённый публичный IPv6. Yggdrasil перезапускается при настройке, поэтому его существующие соединения могут кратковременно прерваться. При `ipv6.disable=1` в загрузке ядра требуется исправление загрузки и перезагрузка VPS.
- UFW с `IPV6=yes` настраивается точечными разрешениями. При нестандартном запрещающем INPUT firewall скрипт остановится; после самостоятельной настройки можно использовать `--firewall-ready`. Docker NAT/FORWARD/DOCKER-USER и чужие таблицы не сбрасываются. Наш фильтр затрагивает только VLESS и выбранные SSH-порты на Yggdrasil-адресе; API ноды и прочие сервисы сохраняют свою прежнюю политику доступа.
- Если уже установлен отдельный **BrainDeLook/yggdrasil-vless** с таблицей `ygg_vless_access`, скрипт остановится до изменений: её общий запрет остальных Yggdrasil-портов конфликтует с нативным режимом. Не выключайте эту таблицу вслепую: она защищает старые VLESS/SSH. Для первого теста используйте VPS Remnanode без старого отдельного прокси; перенос старого стека требует отдельной миграции его firewall и клиентов.
- Пользовательские Host mapper, нестандартные перенаправления портов и внешние секреты Reality пока не поддерживаются. Hysteria2/gRPC/XHTTP могут продолжать работать рядом, но для нового Yggdrasil Host выбирайте обычный TCP/RAW Reality inbound.
- При ошибке Host не публикуется до завершения локальных проверок. Уже установленные пакеты/Yggdrasil/правила могут остаться: это не глобальная транзакция и автоматического отката чужих сетевых настроек нет. Исправьте причину и повторите запуск. POST не повторяется вслепую; следующий запуск ищет ранее созданный Host.

## Файлы и диагностика

- `/etc/remnawave-yggdrasil/state.json` — состояние без API-токена.
- `/etc/remnawave-yggdrasil/client*` — личная ссылка/конфигурация при выбранном пользователе, права 600.
- `/etc/remnawave-yggdrasil/backups/` — предыдущие наши настройки и копия исходного конфига Yggdrasil; могут содержать закрытый ключ Yggdrasil, каталог закрыт.
- `/opt/remnawave-yggdrasil/` — установленный менеджер.

```bash
systemctl status yggdrasil remna-ygg-network remna-ygg-access
journalctl -u yggdrasil -u remna-ygg-network -u remna-ygg-access -n 80 --no-pager
nft list table inet remnawave_yggdrasil
ip -6 addr
ss -6 -lntp
```

Если включён отдельный SSH: `journalctl -u remna-ygg-ssh -n 40 --no-pager`.

Отключение Host в панели убирает его из подписок, но не отзывает уже выданный UUID существующего inbound. Для отзыва доступа используйте пользователей/доступы панели или списки firewall; не удаляйте фильтр вслепую. Удаление добавленных systemd-файлов и правил не должно затрагивать Remnanode и её public listener.

## Проверки

`python3 -m unittest discover -s tests -v` проверяет API-границу, сохранение source Host/профиля/squads, повторный запуск и защиту от пересылки API-токена при redirect.

GitHub Actions запускает настоящие Remnawave Panel и Node, локального пира Yggdrasil и установщик на Ubuntu. Проверяются VLESS Reality/HTTPS до и после, неизменность профиля/исходного Host/контейнеров/Docker NAT, повторная установка, включение IPv6 при отключённом default и списки доступа через network namespace. Это проверка эквивалентного стека, не выполнение сторонних интерактивных установщиков и не гарантия для всех вручную изменённых серверов.
