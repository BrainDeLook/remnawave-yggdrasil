# RemnaYgg

[![Проверки](https://github.com/BrainDeLook/remnawave-yggdrasil/actions/workflows/check.yml/badge.svg)](https://github.com/BrainDeLook/remnawave-yggdrasil/actions/workflows/check.yml)
[![Версия](https://img.shields.io/badge/версия-v0.3.5-blue)](https://github.com/BrainDeLook/remnawave-yggdrasil/releases/tag/v0.3.5)

**RemnaYgg** добавляет подключение через **Yggdrasil** к уже работающей ноде Remnawave. По желанию мастер также настроит **Hysteria2, gRPC и XHTTP**. Серверы появятся в обычной подписке, а управлять доступом вы продолжите через панель.

> [!IMPORTANT]
> Запускайте скрипт **на VPS действующей ноды**, от root. Сначала установите Remnanode через eGames или вручную и проверьте обычный VLESS TCP Reality. На ПК или роутере этот установщик запускать не нужно.

**Навигация:** [Установка](#установка) · [Мастер](#шаги-мастера) · [Yggdrasil и IP](#доступ-через-yggdrasil) · [SSH](#ssh-через-yggdrasil) · [Панель](#управление-доступом-в-панели) · [Другие ноды](#влияние-на-другие-ноды) · [Помощь](#если-что-то-не-работает)

## Что получится

| Подключение | Порт по умолчанию | Что потребуется |
|---|---|---|
| Обычный VLESS TCP Reality | Существующий, обычно TCP 443 | Уже работает; его исходный inbound сохраняется |
| Hysteria2 | UDP 443 | Действующий TLS-сертификат домена |
| VLESS gRPC Reality | TCP 8443 | Работающая нода Remnawave |
| VLESS XHTTP Reality | TCP 4443 | Работающая нода Remnawave |
| VLESS Reality через Yggdrasil | TCP 1488 | Доступ к сети Yggdrasil у клиента или его роутера |

Выбирайте только нужные дополнения. Для каждого мастер добавит отдельный **inbound** — точку входа в Xray — и **Host**, то есть запись сервера для подписки. Если подходящий дополнительный inbound уже есть в профиле, мастер использует его настройки.

Все подключения обслуживает существующая Remnanode. Второй постоянно работающий proxy core, веб-конвертер и приложение для ПК для установки не нужны.

### Названия серверов

Введите общее название **без протокола**, например `🇳🇱 Нидерланды`. Дополнения получат имена:

```text
🇳🇱 Нидерланды Histeria
🇳🇱 Нидерланды GRPC
🇳🇱 Нидерланды XHTTP
🇳🇱 Нидерланды Ygg
```

Исходный TCP Host сохраняет своё имя, например `🇳🇱 Нидерланды TCP`. При обновлении старые длинные имена мастера сокращаются автоматически; ручные имена сохраняются.

## Что подготовить

| Нужно | Где взять или как проверить |
|---|---|
| Панель Remnawave 3.x и рабочая нода | Обычный VLESS TCP Reality уже подключается в клиенте |
| Подходящая VPS | Debian 12+ или Ubuntu 22.04+, systemd, amd64/arm64 |
| Контейнер Remnanode | Называется `remnanode`, работает с `network_mode: host` |
| URL панели | Например, `https://panel.example.com`, без `/dashboard` и пути подписки |
| API-токен | **Настройки Remnawave → Токены API** |
| Только для нового Hysteria2 | Сертификат домена и доступный для записи mount `/dev/shm:/dev/shm` в контейнере |

Токену нужны чтение и изменение **Config Profiles, Nodes, Hosts и Internal Squads**. Для первого запуска подойдёт отдельный временный токен с полным доступом; после установки его можно отозвать. Ввод скрытый, токен не сохраняется.

При защите панели секретной ссылкой eGames подготовьте **исходную ссылку из установки или меню eGames**. Обычный адрес панели после входа может уже не содержать секретного параметра.

> [!NOTE]
> v0.3.5 — предварительный выпуск. Мастер покажет план до применения. При общем профиле заранее прочитайте раздел [о влиянии на другие ноды](#влияние-на-другие-ноды).

## Установка

Подключитесь по SSH **к VPS нужной ноды**, войдите как `root` и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/BrainDeLook/remnawave-yggdrasil/main/install.sh -o /tmp/remna-ygg-install.sh && bash /tmp/remna-ygg-install.sh
```

Если `curl` не найден, сначала установите его и повторите запуск:

```bash
apt-get update && apt-get install -y curl ca-certificates
```

### Только Yggdrasil, без ввода IP клиентов

1. Выберите ноду этой VPS и её рабочий **VLESS TCP Reality Host**.
2. В списке дополнений оставьте отмеченным только **Yggdrasil**. В текстовом режиме введите **`4`**.
3. Задайте название и выберите внутренние сквады, которым нужен доступ.
4. Выберите **«По подписке»**. В текстовом режиме это вариант **`1`**.
5. На вопрос об SSH ответьте **«нет»**, если управление VPS через Yggdrasil не требуется.
6. Проверьте план и подтвердите применение.
7. Обновите обычную подписку в VPN-клиенте и выберите сервер с окончанием **Ygg**.

IP устройств в этом сценарии вводить не нужно. Клиенту всё равно необходим доступ к сети Yggdrasil — напрямую или через роутер.

## Шаги мастера

### Экранное меню через SSH

При обычном запуске в SSH-терминале открывается главное меню **RemnaYgg**. В широком окне его встречает крупная ASCII-шапка с голубым градиентом; в компактном — короткий заголовок, чтобы оставить место для вопросов и выбора. Каждый этап показывается на отдельном чистом экране: пояснение, вопрос и варианты выбора расположены компактно сверху. Длинные пояснения и журналы прокручиваются; подсказка появляется только там, где есть скрытый текст.

**Палитра выбирается автоматически** — и командой установки выше, и последующим запуском `remnawave-yggdrasil`:

- терминал сообщает 256 цветов или truecolor → голубой градиент;
- обычный `xterm` / `xterm-color` → короткий запрос возможности читать 256-цветную палитру;
- поддержки нет или ответ не получен → простая палитра;
- `NO_COLOR` → без цветов.

Вручную добавлять `TERM=...` к команде не нужно. Запрос занимает не более 0,6 секунды, не меняет цвета терминала и не сохраняет настройки оболочки. Техническая основа — [запрос палитры OSC 4 в Xterm](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html#h2-Operating-System-Commands). В мультиплексорах tmux/screen используется заявленный ими режим: неподтверждённые возможности не включаются принудительно.

До подтверждения можно вернуться назад и изменить ответы. Токен остаётся только в памяти текущего запуска и не показывается при возврате. После подтверждения возврат к вопросам закрывается: идут реальные изменения VPS и панели.

Минимальный размер окна — **54 × 18**; для длинных пояснений удобнее **100 × 30**. При уменьшении окна мастер предложит увеличить его, сохранив ввод. Пункт «Yggdrasil и SSH» открывает мастер только для Yggdrasil с обычной проверкой панели и планом применения.

В «Моих подключениях» отдельно показаны нода и панель, подключения, порядок обновления личной подписки, доступ к VPN и SSH, результаты проверок. Это сохранённый снимок: он не подменяет текущие настройки панели. Проверка TCP-слушателя не означает проверку VPN-авторизации или HTTPS; Hysteria2 проверяется в клиенте по UDP.

В диагностике доступны состояния служб, журналы Yggdrasil, Remnanode, сертификата Hysteria2, установки и загрузчика. Ошибки выделены красным, предупреждения — жёлтым, этапы — бирюзовым. Отсутствующая необязательная служба помечается «не настроено». Подробный журнал установки: `/var/log/remnawave-yggdrasil/installer.log`, доступен только root. Известные мастеру секреты скрываются в выводе и в этом журнале; перед публикацией сторонних журналов всё равно проверьте их содержимое.

Для прежнего текстового ввода:

```bash
bash /tmp/remna-ygg-install.sh --plain
```

Автоматический запуск с `--yes`, вывод в файл, `--check` и `--result` используют обычный текст. При отсутствии поддержки экранного интерфейса мастер также перейдёт к текстовому вводу.

### Порядок настройки

| Шаг | Что выбрать или ввести | Пояснение |
|---|---|---|
| **1. Панель** | URL и API-токен | Нужен адрес панели, а не VPN-сервера или подписки |
| **2. Нода и Host** | Ноду этой VPS и её работающий TCP Reality Host | По нему мастер найдёт профиль и настройки Reality |
| **3. Дополнения и имя** | Отметьте дополнения и введите общее название | В текстовом режиме: `4` — Yggdrasil; `1 4` — Hysteria2 и Yggdrasil; `1 2 3 4` — всё |
| **4. Сквады** | Группы пользователей для каждого дополнения | Enter без выбора создаст **новый Host выключенным**; права можно настроить позднее |
| **5. Yggdrasil и SSH** | Режим доступа и, при необходимости, адреса | Этот шаг появляется только при выборе Yggdrasil |
| **6. Hysteria2** | Сертификат, если его не удалось найти | Для VLESS Reality, включая Yggdrasil, TLS-сертификат не нужен |
| **7. План** | Проверьте ноду, профиль, порты и сквады | Изменения применяются после явного ответа «да» |

В текстовом режиме строка **`Enter → …`** показывает предлагаемый ответ. В экранном режиме значения уже подставлены в поля и списки. При вводе токена символы скрыты.

Цвета: **бирюзовый** — раздел; **жёлтый** — вопрос; **зелёный** — выбранное; **синий** — пример; **янтарный** — замечание; **красный** — ошибка.

## Доступ через Yggdrasil

Yggdrasil — сеть, по которой клиент добирается до VLESS-сервера. VPN-учётную запись и её разрешения по-прежнему проверяет Remnawave.

### Какой режим выбрать

| Режим | Как работает | Когда подходит |
|---|---|---|
| **1. По подписке** | Нужна действующая VPN-учётная запись с доступом к inbound. Списка IP нет | Для обычной выдачи подписок себе и друзьям |
| **2. По подписке и списку IP** | Дополнительно проверяется IPv6 устройства или его LAN-подсеть | Для входа только с перечисленных устройств и сетей |

При новой установке предлагается **режим 1**. У существующей установки сохраняется прежний режим: чтобы убрать ограничение по IP, явно выберите **1**. Старый VPN-список сохраняется для возврата к режиму **2**.

В режиме 1 подключаться можно из сети Yggdrasil `200::/7`, включая LAN-адреса `300:…`. Рабочая VPN-ссылка, переданная другому человеку, также позволит ему подключиться: подписка не привязана к устройству.

### Какие адреса вводить в режиме 2

В OpenWrt откройте **Сеть → Интерфейсы → Yggdrasil**. Мастер запросит оба значения:

| Поле на роутере | Что означает | Что вводить |
|---|---|---|
| **IPv6** | Адрес роутера; с него подключается Тахион | `200:1111:2222:3333:4444:5555:6666:7777` — **без `/7`** |
| **IPv6-PD** | Подсеть устройств LAN | `300:1111:2222:3333::/64` — **с `/64`** |

**Это вымышленные примеры — скопируйте свои значения с роутера. Адрес самой VPS здесь не вводится.**

Подсеть `300:…/64` охватывает устройства LAN, даже если полный IPv6 ПК меняется. Отдельный адрес такого ПК не нужен. В каждом поле можно указать несколько значений через пробел — например, для своего роутера и роутера друга.

В режиме 2 нужны оба разрешения: **IP устройства разрешён на VPS**, а **VPN-пользователь имеет доступ к inbound в Remnawave**.

## SSH через Yggdrasil

SSH нужен для управления VPS. Для работы VPN включать его необязательно.

Если ответить **«да»**, мастер запросит **отдельный список IP и подсетей для SSH**. Можно разрешить управление только своему роутеру `200:…` и своей LAN `300:…/64`, оставив другу доступ лишь к VPN. Enter принимает предложенный список; его можно заменить своим.

| Вопрос | Ответ |
|---|---|
| Какие IP разрешать? | Адреса устройств, **с которых вы будете управлять VPS** |
| Куда подключаться? | К **IPv6 самой VPS**, показанному в результате установки |
| Какой логин? | Существующий Linux-пользователь VPS, например `root` |
| Какой ключ или пароль? | Существующий ключ или пароль этого пользователя VPS |
| Нужен Username VPN-пользователя? | Нет. VPN-пользователь Remnawave и SSH-пользователь VPS — разные учётные записи |

Готовую SSH-команду мастер покажет в конце. В Bitvise укажите IPv6 VPS в поле **Host**, а порт и пользователя возьмите из результата. Публичный SSH скрипт не перенастраивает.

## Управление доступом в панели

### Выдать сервер пользователю

1. В **Внутренних сквадах** разрешите нужному скваду новый inbound.
2. В **Пользователях** назначьте пользователю этот сквад.
3. В **Хостах** проверьте, что Host включён и его ограничения разрешают этот сквад.
4. Попросите пользователя обновить обычную личную подписку в клиенте.

Если сквады выбраны при установке, мастер уже добавит им доступ к inbound и ограничит ими показ **нового** Host. Ручные ограничения существующих Host сохраняются. Внешние сквады и собственные шаблоны подписок могут дополнительно фильтровать выдачу.

> [!TIP]
> Для каждого нового пользователя не нужно запускать установщик или создавать общий UUID. Выдайте доступ в панели и передайте его личную подписку.

### Отозвать доступ

Отключите VPN-пользователя либо уберите доступ к inbound через все его сквады. **Одного скрытия Host недостаточно:** оно убирает сервер из подписки, но не отзывает ранее скопированные реквизиты.

### Что где настраивается

| Раздел | За что отвечает |
|---|---|
| **Профили** | Настройки inbound, маршрутизация и DNS |
| **Ноды** | Какие inbound включены на конкретной VPS |
| **Внутренние сквады** | Каким VPN-пользователям разрешены inbound |
| **Хосты** | Название и параметры сервера в подписке, ограничения его показа |

## Влияние на другие ноды

**Ноды с отдельными профилями мастер не перенастраивает.** Docker Compose, правила Docker и Host других нод сохраняются.

> [!WARNING]
> При **общем профиле** сама Remnawave после изменения профиля или прав сквада может перезапустить Xray на всех его нодах. Возможен короткий разрыв соединений. Мастер показывает имена соседних нод до применения; их списки активных inbound сохраняются.

Для независимого обслуживания назначьте ноде отдельный профиль заранее. Новый Yggdrasil inbound автоматически активируется только на выбранной ноде.

Права сквада относятся к **inbound**, а не к одной VPS. Если он уже включён на нескольких нодах, право на него действует везде. Ограничения Host управляют показом в подписке, а не привязкой скопированных реквизитов к серверу.

Обновление сертификата нашим таймером перезапускает **только локальный контейнер Remnanode**. Это кратко затронет все протоколы этой VPS; контейнеры других нод таймер не перезапускает.

## Обновление и повторный запуск

Запустите ту же [команду установки](#установка) на VPS ноды и выберите нужные уже установленные дополнения.

- Настроенные мастером inbound и Host переиспользуются; ручные правки сохраняются.
- Старые длинные имена мастера сокращаются у выбранных дополнений.
- Выбор сквадов **добавляет** разрешения; отзывайте их в панели.
- Пропущенный при повторном выборе протокол **не удаляется**.
- Режим доступа и идентичность Yggdrasil сохраняются.

Не запускайте несколько установщиков одновременно и не редактируйте профиль во время применения. VPS и панель не образуют общую транзакцию: при ошибке часть шагов может завершиться. Исправьте причину и повторите запуск — мастер сверится с текущим состоянием.

### Полезные команды

**Показать план без применения профиля и firewall:**

```bash
bash /tmp/remna-ygg-install.sh --check
```

Сначала скачайте установщик командой выше. Загрузчик при необходимости установит Python/curl даже при `--check`.

**Снова показать итог последней установки:**

```bash
remnawave-yggdrasil --result
```

Это сохранённый результат: последующие изменения в панели он не запрашивает.

## Если что-то не работает

| Ситуация | Что проверить |
|---|---|
| **API вернул HTML или страницу входа** | При защите eGames введите исходную секретную ссылку из установки/меню, например `https://panel.example.com/auth/login?ИМЯ=ЗНАЧЕНИЕ`, или Cookie `name=value`. Токен не обходит внешнюю защиту |
| **API вернул 401/403** | Срок и права токена, доступность API через reverse proxy |
| **Сервер не появился в подписке** | Доступ пользователя к inbound, ограничения и включённость Host; затем обновите подписку |
| **В другом клиенте Yggdrasil работает, в Тахионе — нет** | Некоторые версии Тахиона требуют `bind_interface: "yggdrasil"` на роутере. Обычная VLESS-подписка это поле не передаёт |
| **В режиме 2 не подключается роутер или ПК** | Указаны ли и `200:…` без `/7`, и LAN `300:…/64`; разрешён ли inbound пользователю |
| **Мастер просит сертификат** | Он нужен Hysteria2. Если действующая пара не найдена автоматически, укажите пути. Новый сертификат мастер не выпускает |
| **VPN работает, SSH — нет** | Включён ли SSH через Yggdrasil, разрешён ли IP источника в SSH-списке, выбран ли адрес VPS и верный Linux-пользователь |
| **Нестандартный firewall или отдельный `ygg-vless`** | Установка может остановиться ради сохранения правил. См. [сетевую справку](docs/advanced.md#сеть-и-firewall) |

Журналы на VPS:

```bash
journalctl -u yggdrasil -u remna-ygg-network -u remna-ygg-access -u remna-ygg-ssh -u remna-hy2-certs -n 80 --no-pager
docker logs --tail 80 remnanode
```

В экранном меню откройте **«Диагностика и журналы»**. Журнал последнего подтверждённого применения хранится в `/var/log/remnawave-yggdrasil/installer.log` с доступом только root. Он содержит этапы и вывод системных команд; API-токен, скрытый ввод и вывод `docker inspect` туда не записываются.

## Справка и проверка проекта

- [Технические изменения на VPS, сертификаты и параметры CLI](docs/advanced.md)
- [Архивная инструкция для режима 0.1.x](docs/legacy-v0.1.md)
- [Выпуски и установочные файлы](https://github.com/BrainDeLook/remnawave-yggdrasil/releases)
- [Автоматические проверки](https://github.com/BrainDeLook/remnawave-yggdrasil/actions/workflows/check.yml)

Проверяются преобразование профиля, маршрутизация, сертификаты и имена. Полный стенд использует настоящую панель, три Remnanode и Yggdrasil: проверяет HTTPS через все транспорты, соседние ноды с общим и отдельным профилем, права сквадов, сетевые ограничения и повторный запуск. Runtime-проверки выполняются на amd64; для arm64 закреплены официальные бинарники.

Используется API [Remnawave](https://github.com/remnawave/backend). Совместимость и рабочий процесс основаны на [Rrezzak09VPN](https://github.com/Rrezzak09VPN/remnanode-VLESS-Reality-Hysteria2) и [eGames](https://github.com/eGamesAPI/remnawave-reverse-proxy). Лицензия — MIT.
