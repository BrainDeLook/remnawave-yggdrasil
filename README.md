# Remnawave: дополнительные протоколы и Yggdrasil

Установка **на VPS существующей ноды Remnawave**. Как в обычной ноде: каждый дополнительный протокол имеет отдельный inbound в профиле, Host и права внутренних сквадов. Существующий VLESS TCP Reality сохраняется. Второго постоянно работающего proxy core нет.

Основа рабочего процесса — [Rrezzak09VPN/remnanode-VLESS-Reality-Hysteria2](https://github.com/Rrezzak09VPN/remnanode-VLESS-Reality-Hysteria2). Мы независимо реализовали автоматическую настройку профиля через API, добавили опциональный Yggdrasil и локальное приложение-конвертер для Windows. Страница upstream не разворачивается на VPS, код веб-конвертера не загружается и конфигурация туда не отправляется.

**v0.2.1 — предварительный выпуск с новым режимом, который изменяет профиль через API. Сначала проверьте на одной тестовой ноде.**

## Что можно выбрать

| Дополнение | Порт по умолчанию | Управление |
|---|---|---|
| Базовый VLESS TCP/RAW Reality | прежний, обычно TCP 443 | Существующий inbound, без изменений |
| Hysteria2 | UDP 443 | Отдельный inbound, сертификат домена |
| VLESS gRPC Reality | TCP 8443 | Отдельный inbound |
| VLESS XHTTP Reality | TCP 4443 | Отдельный inbound |
| VLESS Reality через Yggdrasil | TCP 1488 | Отдельный inbound, собственные списки сетевого доступа |

Выбирайте любое сочетание. Yggdrasil и SSH через него необязательны. Это VLESS через сеть Yggdrasil, а не новый протокол Xray.

## Перед установкой

1. Нода уже установлена через eGames или вручную и подключена к Remnawave 3.x. Обычный VLESS TCP Reality работает.
2. VPS: Debian 12+/Ubuntu 22.04+, systemd, amd64/arm64, Docker-контейнер `remnanode`, `network_mode: host`.
3. Для Hysteria2: общий mount `/dev/shm:/dev/shm` и действующий TLS-сертификат домена исходного Host. Используется существующая установка сертификатов; новые домены/сертификаты автоматически не выдаются.
4. Создайте отдельный API-токен: чтение и изменение Config Profiles, Nodes, Hosts, Internal Squads. Можно временный полный доступ. VPN Username не нужен.
5. У API должен быть доступ с VPS. Cookie-защита eGames поддерживается: сохраните **исходную секретную ссылку входа** из установки/меню eGames. TinyAuth/Cloudflare Access требуют своего штатного API-доступа.

## Установка: что вводить

Запустите **на VPS выбранной ноды**, от root:

```bash
curl -fsSL https://raw.githubusercontent.com/BrainDeLook/remnawave-yggdrasil/main/install.sh -o /tmp/remna-ygg-install.sh && bash /tmp/remna-ygg-install.sh
```

Если curl отсутствует: `apt-get update && apt-get install -y curl ca-certificates`.

Мастер объясняет каждый шаг:

1. **URL панели** — `https://panel.example.com`. Не адрес ноды, не подписка. API-токен вводится скрыто и не сохраняется. При HTML-заглушке мастер спросит скрыто полную ссылку eGames вида `https://panel.example.com/auth/login?СЕКРЕТНОЕ_ИМЯ=СЕКРЕТНОЕ_ЗНАЧЕНИЕ`. Браузер после входа обычно убирает секрет из адресной строки. Ссылку и токен не присылайте в чат.
2. **Нода этой VPS** — выберите её название в панели, затем исходный VLESS TCP Reality Host. Мастер показывает адрес API и профиль. Не выбирайте другую VPS.
3. **Дополнения** — номера через пробел: `4` только Yggdrasil, `1 4` Hysteria2 + Yggdrasil, `1 2 3 4` все. Название сервера выбираете сами.
4. **Внутренние сквады** — отдельно для каждого дополнения выберите группы VPN-пользователей. Enter создаёт новый Host выключенным до настройки доступа в панели. Для существующих Host ручные ограничения сохраняются.
5. **Yggdrasil и SSH**, если выбраны: адреса устройств и LAN описаны ниже.

Для Hysteria2 мастер автоматически проверяет содержимое всех сертификатов `/etc/letsencrypt/live/*/fullchain.pem`, срок действия и соответствие домену Host, включая wildcard и папки с суффиксом `-0001`. Имя папки не обязано совпадать с доменом. Если подходит несколько сертификатов, выбирается действующий с наибольшим оставшимся сроком. Путь спрашивается только при отсутствии подходящего сертификата. Для VLESS Reality/Yggdrasil TLS-сертификат не требуется.
6. **План** — профиль, inbound, порты, сквады. До явного «да» рабочие настройки не применяются. `--yes` означает заранее согласованное применение в автоматическом режиме.

После применения мастер добавляет отсутствующие inbound в **существующий профиль**, активирует их только на выбранной ноде, создаёт Host и добавляет права выбранным сквадам. Если профиль общий для нескольких нод, его JSON пополнится, но список активных inbound остальных нод не меняется. В панели возможна штатная перезагрузка Xray при изменении профиля.

### Какие IP вводить для Yggdrasil

На OpenWrt: **Сеть → Интерфейсы → Yggdrasil**.

| Поле роутера | Пример | Ввод в мастер |
|---|---|---|
| IPv6 | `200:1111:2222:3333:4444:5555:6666:7777/7` | `200:1111:2222:3333:4444:5555:6666:7777` **без /7** |
| IPv6-PD | `300:1111:2222:3333::/64` | `300:1111:2222:3333::/64` **с /64** |

Первое разрешает Тахиону и самому роутеру соединение с VPS. Второе — устройствам всей LAN, включая временные адреса ПК внутри этой подсети. Это вымышленные примеры: копируйте свои значения. Отдельный IP ПК из разрешённой LAN не требуется. Адрес самой VPS сюда не вводите.

В обоих полях можно несколько значений через пробел, например для друзей. `/64` разрешает всю соответствующую LAN. Доступ к VPN требует одновременно разрешения IP на VPS и доступа пользователя в Remnawave.

**SSH — отдельное разрешение**, о нём мастер спрашивает перед вводом адресов. Если включили, укажите собственный список IP/подсетей; Enter предлагает те же устройства. Друг может получить только VPN. Для SSH по-прежнему нужен существующий аккаунт/ключ/пароль. Публичный SSH не перенастраивается.

## Как управлять после установки

- **Профили**: каждый протокол — отдельный inbound. Существующие inbounds, routing, DNS и другие разделы сохранены.
- **Ноды**: включайте/выключайте новые inbound на конкретной ноде.
- **Внутренние сквады**: независимо разрешайте Yggdrasil, обычный TCP и остальные inbound.
- **Хосты**: меняйте адрес/порт/SNI/название и ограничения сквадов. Если сквады выбраны, новые Host создаются в режиме «разрешить только выбранным сквадам». Если не выбраны — Host выключен; сначала настройте сквады для inbound и Host, затем включите Host. Для выдачи нужны и доступ к inbound, и разрешение Host хотя бы через один сквад пользователя.
- При External Squads и собственных шаблонах подписки учитывайте их дополнительные фильтры.
- Обновите обычную личную подписку в клиенте. Никакого общего UUID и обязательной ручной ссылки нет.

На повторном запуске прежние inbound не переписываются, существующие Host не дублируются и их ручные правки не отменяются. Выбор сквадов **добавляет** разрешения inbound; для уже созданного Host его ограничения редактируются в панели. Удаление/отзыв доступа выполняйте в панели: мастер не удаляет протоколы, если вы просто не выбрали их при повторном запуске. Добавление протоколов — не транзакция между VPS и панелью: после сетевой ошибки часть шагов может завершиться. Повторный запуск сверяется с текущими данными; не повторяет POST вслепую.

### Тахион / OpenWrt

Серверная часть не может задавать сетевой интерфейс чужого роутера. В некоторых версиях Тахиона `auto_detect_interface` направляет соединение Yggdrasil неправильно. В таком клиенте требуется `bind_interface: "yggdrasil"` либо соответствующая постоянная настройка самого Тахиона. VLESS-ссылка и стандартная подписка не передают это поле. **Этот выпуск не исправляет Тахион и не обещает отсутствие клиентских настроек во всех его версиях.** Inbound/Host/сквады работают штатно независимо от этой особенности клиента.

## Локальный конвертер для ПК — необязательно

Основной установщик уже меняет профиль через API, поэтому конвертер для установки не нужен. Он пригодится, если вы предпочитаете сначала подготовить и проверить профиль вручную.

Скачайте **RemnawaveConverter.exe** из [релизов](https://github.com/BrainDeLook/remnawave-yggdrasil/releases). Для Windows x64 это отдельная программа: Python устанавливать не нужно, сайт/сервер не нужен, сеть не используется.

1. Экспортируйте JSON профиля Remnawave. Откройте файл в программе или вставьте JSON.
2. Выберите базовый TCP Reality inbound и галочками нужные дополнения.
3. Нажмите «Преобразовать», проверьте результат, сохраните **в новый файл**.
4. Если применяете вручную: подготовьте VPS установщиком, вставьте JSON в профиль, активируйте inbound на ноде, создайте Host с правильными SNI/портами и назначьте сквадам.

Конвертер сохраняет исходные inbound, routing/DNS и реальные `dest`/`target`, `xver`, ключи и SNI Reality; не заменяет target на чужой домен. Результат содержит приватные ключи — не публикуйте его. Совпадение портов/повторение tag вызывает понятную ошибку. Существующие gRPC/XHTTP/Hysteria2 inbound переиспользуются без дублирования. Снять галочку означает «не добавлять», не «удалить существующее».

Без EXE: `python desktop.py` (Python с Tk). CLI:

```bash
python converter.py source.json result.json --base japanelo-vless-443 --protocol ygg
```

## Проверка и автоматизация

```bash
bash /tmp/remna-ygg-install.sh --check
remnawave-yggdrasil --result
```

`--check` проверяет API и план, не применяет профиль/firewall. Загрузчик может предварительно установить Python/curl. `--result` показывает состояние последнего запуска, а не опрашивает панель в реальном времени.

Для автоматизации: `--panel`, `--node UUID`, `--source-host UUID`, повторяемые `--protocol hy2|grpc|xhttp|ygg`, `--squad UUID`, `--allow-ip`, `--ssh-allow-ip`, `--no-ssh`/`--ssh`, `--cert`, `--key`, `--peer`, `--ygg-port`. `--token-file` и `--access-file` требуют `600`; либо переменные `REMNAWAVE_API_TOKEN` и `REMNAWAVE_PANEL_ACCESS`. Секреты аргументами не принимаются. С `--yes` выбор ноды/Host при нескольких вариантах должен быть однозначным.

## Что меняется на VPS

- Yggdrasil 0.5.14 для amd64/arm64 с проверкой SHA256, только если выбран. Уже установленная идентичность 0.5.x сохраняется.
- IPv6 включается только на loopback и TUN Yggdrasil; WAN/default route/DNS не переделываются.
- Отдельный Yggdrasil inbound слушает IPv6 wildcard на выделенном порту, чтобы запуск Xray не зависел от готовности TUN. **nftables запрещает этот порт на всех внешних адресах кроме собственного Yggdrasil и разрешённых клиентов**. Публичные gRPC/XHTTP/Hysteria2 открываются точечно в активном UFW. UFW не включается автоматически. При нестандартном INPUT firewall нужен `--firewall-ready` после ручной настройки разрешений.
- Для Hysteria2 ключ в `/dev/shm` имеет `600`. Таймер восстанавливает файлы после загрузки и проверяет изменения раз в час; Remnanode перезапускается только при изменении файлов. Существующее обновление сертификата продолжает работать.
- Резервная копия JSON профиля и план: `/etc/remnawave-yggdrasil/backups/` (только root). API-токен/секретная ссылка туда не записываются.
- Docker Compose, Docker NAT/FORWARD и публичный SSH не переписываются. Старые cron сторонних скриптов не удаляются; если они настроены перезапускать ноду ежедневно, они продолжат это делать.

Не запускайте установщики одновременно и не меняйте профиль в панели во время применения: API не предоставляет атомарную транзакцию с firewall. Защита от изменения профиля проверяет состояние непосредственно перед PATCH, но полностью исключить одновременную запись другого администратора нельзя.

Предыдущий режим 0.1.x создавал только дополнительный Host на старом inbound. Его Host автоматически не удаляется и ограничения сохраняются; после проверки нового отдельного inbound старый Host можно отключить в панели. Это два разных подключения. [Старая инструкция](docs/legacy-v0.1.md).

Unit-тесты API и конвертера; полный CI Ubuntu с настоящими Panel/Node, Yggdrasil, VLESS HTTPS, отдельными inbound/сквадами, проверкой сетевого доступа и повторного запуска.
