# Remnawave: дополнительные протоколы и Yggdrasil

Запустите мастер **на VPS уже работающей ноды Remnawave**, выберите дополнения и обновите подписку в клиенте. Мастер установит зависимости, добавит отдельные inbound в существующий профиль и создаст Host для каждого дополнения. Доступом дальше можно управлять в обычной панели: через ноды, внутренние сквады и Host.

Существующий VLESS TCP Reality сохраняется. Все подключения обслуживает установленная Remnanode — второй постоянно работающий proxy core не нужен. Username VPN-пользователя, ручное преобразование JSON и приложение для ПК для установки не требуются.

Рабочий процесс основан на [Rrezzak09VPN/remnanode-VLESS-Reality-Hysteria2](https://github.com/Rrezzak09VPN/remnanode-VLESS-Reality-Hysteria2). Здесь настройка профиля и прав выполняется через API Remnawave; Yggdrasil добавляется по выбору. Веб-конвертер на VPS не устанавливается, конфигурация на сторонний сайт не отправляется.

**v0.2.4 — предварительный выпуск. Мастер изменяет профиль через API; сначала проверьте его на одной тестовой ноде.**

## Что можно добавить

| Подключение | Порт по умолчанию | Как работает |
|---|---|---|
| Базовый VLESS TCP/RAW Reality | прежний, обычно TCP 443 | Уже существующий inbound, без изменений |
| Hysteria2 | UDP 443 | Отдельный inbound; нужен TLS-сертификат домена |
| VLESS gRPC Reality | TCP 8443 | Отдельный inbound |
| VLESS XHTTP Reality | TCP 4443 | Отдельный inbound |
| VLESS Reality через Yggdrasil | TCP 1488 | Отдельный inbound; вход по подписке, список IP по выбору |

Можно выбрать любое сочетание дополнений. Yggdrasil и SSH через него включаются отдельно. Yggdrasil здесь — сеть, по которой клиент соединяется с VLESS-сервером, а не новый протокол Xray.

Названия Host имеют общий вид: `🇳🇱 Нидерланды Histeria`, `🇳🇱 Нидерланды GRPC`, `🇳🇱 Нидерланды XHTTP`, `🇳🇱 Нидерланды Ygg`. Флаг и название задайте в мастере один раз. Исходный TCP Host сохраняет своё имя, например `🇳🇱 Нидерланды TCP`. При обновлении старые длинные имена, точно соответствующие формату мастера, сокращаются автоматически. Ручные имена и остальные настройки Host сохраняются.

## Перед запуском

- **Рабочая нода.** Remnawave 3.x, нода установлена через eGames или вручную. Обычный VLESS TCP Reality уже работает.
- **VPS.** Debian 12+ или Ubuntu 22.04+, systemd, amd64/arm64. Docker-контейнер `remnanode` работает с `network_mode: host`.
- **Только для нового Hysteria2.** У контейнера есть доступный для записи mount `/dev/shm:/dev/shm`, на VPS установлен действующий TLS-сертификат домена исходного Host. У уже работающего Hysteria2 проверяются его реальные файлы сертификата через mounts контейнера; его прежнее обновление сохраняется. Новый сертификат мастер автоматически не выпускает.
- **API-токен.** В панели создайте отдельный токен с чтением и изменением Config Profiles, Nodes, Hosts и Internal Squads. Подойдёт временный токен с полным доступом.
- **Доступ к панели с VPS.** Если панель защищена секретной ссылкой eGames, сохраните полную исходную ссылку из установки или меню eGames. Для TinyAuth/Cloudflare Access нужен предусмотренный этими средствами доступ к API.

## Установка

Запустите **от root на VPS той ноды, которую хотите дополнить**:

```bash
curl -fsSL https://raw.githubusercontent.com/BrainDeLook/remnawave-yggdrasil/main/install.sh -o /tmp/remna-ygg-install.sh && bash /tmp/remna-ygg-install.sh
```

Если `curl` не установлен:

```bash
apt-get update && apt-get install -y curl ca-certificates
```

### Как читать мастер

Цвет выделяет назначение строки; подписи сохраняют смысл и без цвета.

| Цвет | Что обозначает |
|---|---|
| Бирюзовый | Заголовок и текущий этап |
| Обычный цвет терминала | Объяснение действия |
| Жёлтый | Вопрос, на который нужно ответить |
| Зелёный | Выбранный вариант или успешный результат |
| Синий | Пример, команда, адрес или значение для копирования |
| Янтарный | Предупреждение или условие, на которое нужно обратить внимание |
| Красный | Ошибка и причина остановки |

Строка «Enter → …» показывает значение по умолчанию: нажмите Enter, чтобы его принять. Для списков мастер объясняет, что означает пустой ввод. Цвет отключается, если задана переменная `NO_COLOR`, терминал обозначен как `TERM=dumb` или вывод направлен в файл/канал. Например:

```bash
NO_COLOR=1 bash /tmp/remna-ygg-install.sh
```

### Что спросит мастер

1. **Адрес панели и API-токен.** Введите, например, `https://panel.example.com`. Это адрес веб-панели, а не адрес ноды и не ссылка подписки. Токен вводится скрыто и не сохраняется. Если API вернёт HTML-заглушку eGames, мастер запросит полную секретную ссылку входа вида `https://panel.example.com/auth/login?СЕКРЕТНОЕ_ИМЯ=СЕКРЕТНОЕ_ЗНАЧЕНИЕ`. После входа браузер обычно убирает секрет из адресной строки, поэтому копируйте исходную ссылку из eGames. Токен и секретную ссылку не публикуйте.
2. **Нода и исходное подключение.** Выберите именно ноду этой VPS, затем её работающий VLESS TCP Reality Host. Мастер покажет выбранную ноду, адрес API и профиль, чтобы их можно было сверить.
3. **Дополнения и название.** Введите номера через пробел: `4` — только Yggdrasil, `1 4` — Hysteria2 и Yggdrasil, `1 2 3 4` — все дополнения. Названия подключений можно изменить.
4. **Доступ внутренних сквадов.** Для каждого дополнения выберите группы VPN-пользователей. Если пропустить выбор, новый Host будет выключен: права можно настроить в панели позднее. У существующего Host ручные ограничения сохраняются.
5. **Режим доступа Yggdrasil и необязательный SSH.** Выберите «По подписке», чтобы не вводить IP VPN-клиентов, или включите дополнительный список IP. Для SSH всегда нужен отдельный список адресов.
6. **Сертификат Hysteria2.** Мастер сначала ищет подходящий действующий сертификат автоматически. Путь потребуется только тогда, когда подходящего сертификата нет. Для VLESS Reality, включая вариант через Yggdrasil, сертификат не требуется.
7. **План изменений.** Сверьте профиль, inbound, порты и сквады. Рабочие настройки применяются после явного ответа «да». Параметр `--yes` заранее разрешает применение при автоматическом запуске.

Для Hysteria2 проверяется содержимое сертификатов `/etc/letsencrypt/live/*/fullchain.pem`, срок действия и соответствие домену Host. Поддерживаются wildcard-сертификаты и папки с суффиксом `-0001`: имя папки не обязано совпадать с доменом. Если подходит несколько сертификатов, выбирается действующий с наибольшим оставшимся сроком.

После подтверждения мастер дополняет **существующий профиль**, активирует новые inbound только на выбранной ноде, создаёт Host и выдаёт права выбранным сквадам. Если профиль общий для нескольких нод, его JSON пополнится, но списки активных inbound остальных нод останутся прежними. При изменении профиля панель может штатно перезагрузить Xray.

### Влияние на другие ноды

Ноды с отдельными профилями мастер не перенастраивает. Docker Compose, сетевые правила Docker и Host других нод сохраняются.

**У общего профиля есть общий цикл применения:** Remnawave при изменении JSON профиля или прав сквада может перезапустить Xray на всех нодах этого профиля. Возможен короткий разрыв соединений. Мастер показывает имена соседних нод до подтверждения; их списки активных inbound не меняет. Для независимого обслуживания назначьте ноде отдельный профиль заранее.

Права внутреннего сквада относятся к **inbound**, а не к одной ноде. Если переиспользуется inbound, активный на нескольких нодах, добавление сквада разрешает его пользователям этот inbound везде. Host ограничивает показ в подписке; скопированные реквизиты этим не привязываются к одной VPS. Отдельный новый Yggdrasil inbound автоматически активируется только на выбранной ноде.

Новые inbound наследуют правила маршрутизации с `inboundTag` исходного TCP. Существующие inbound и их индивидуальные правила не переписываются. DNS и остальные настройки профиля сохраняются.

### Какие адреса вводить для Yggdrasil

В режиме **«1. По подписке»** IP VPN-клиентов вводить не нужно. Подключение разрешено из всей сети Yggdrasil (`200::/7`, включая адреса LAN `300:…`). VLESS проверяет действующую учётную запись Remnawave и доступ её внутреннего сквада к этому inbound. Выдавайте доступ и отзывайте его через панель. Одна только видимость Host управляет показом в подписке, а не отзывает уже скопированные реквизиты. Переданная другому человеку рабочая ссылка также позволит ему подключаться.

Клиенту по-прежнему нужен маршрут в Yggdrasil: через собственный Yggdrasil или роутер. Этот режим не устраняет необходимость `bind_interface` в тех версиях Тахиона, которым он требуется.

Для новой установки по умолчанию выбран режим по подписке. При обновлении существующий список IP сохраняется: чтобы убрать его, явно выберите вариант **1**. Повторный запуск запоминает режим. Прежний VPN-список сохраняется для возврата к варианту **2**.

В режиме **«2. По подписке и списку IP»** на OpenWrt откройте **Сеть → Интерфейсы → Yggdrasil**. Понадобятся два значения:

| Что копировать | Пример на роутере | Что вводить |
|---|---|---|
| **IPv6** — адрес самого роутера | `200:1111:2222:3333:4444:5555:6666:7777/7` | `200:1111:2222:3333:4444:5555:6666:7777` **без `/7`** |
| **IPv6-PD** — подсеть устройств LAN | `300:1111:2222:3333::/64` | `300:1111:2222:3333::/64` **вместе с `/64`** |

Это вымышленные примеры — подставляйте свои значения.

- Адрес `200:…` разрешает подключение с самого роутера, в том числе из Тахиона.
- Подсеть `300:…/64` разрешает подключение с устройств LAN. Отдельный адрес ПК добавлять не нужно: меняющиеся адреса внутри этой подсети уже разрешены.
- Адрес самой VPS в эти списки не вводится.

В каждом поле можно указать несколько значений через пробел, например адреса своего роутера и роутера друга. Разрешение `/64` распространяется на все устройства соответствующей LAN. В режиме со списком IP клиенту нужны **оба разрешения**: его исходный IP должен быть разрешён на VPS, а VPN-пользователь должен иметь доступ в Remnawave.

**SSH настраивается отдельно.** Мастер сначала спросит, нужен ли SSH через Yggdrasil. Если включить его, появится отдельный список разрешённых IP и подсетей. Enter принимает предложенный список устройств; его можно заменить своим. Так другу можно выдать VPN, оставив SSH только себе. Для входа по SSH по-прежнему требуется существующая учётная запись сервера и её ключ или пароль. Публичный SSH не перенастраивается.

## Управление в панели после установки

| Раздел Remnawave | Что можно менять |
|---|---|
| **Профили** | Настройки каждого отдельного inbound. Новые inbound добавляются в адресованные исходному TCP правила routing; остальные правила и DNS сохраняются. |
| **Ноды** | Включать и выключать inbound на конкретной ноде. |
| **Внутренние сквады** | Независимо разрешать обычный TCP, Yggdrasil и остальные inbound. |
| **Хосты** | Название, адрес, порт, SNI и ограничения по сквадам. |

Для выдачи сервера в подписке пользователю нужны доступ к inbound и разрешение Host хотя бы через один из его сквадов. Если при установке сквады выбраны, новый Host разрешён только им. Если выбор пропущен, сначала настройте права inbound и Host в панели, затем включите Host. External Squads и собственные шаблоны подписок могут дополнительно фильтровать результат.

Обновите обычную личную подписку в клиенте — в ней появятся разрешённые подключения. Общий UUID, отдельная ручная ссылка и повторный запуск установщика для каждого пользователя не нужны.

### Повторный запуск

Мастер переиспользует существующие inbound и Host: не создаёт дубликаты и не отменяет их ручные правки. Исключение — автоматическое сокращение старых имён, точно совпадающих с прежним форматом мастера. Выбор сквадов **добавляет** разрешения на inbound. Ограничения уже созданного Host меняются в панели.

Отзывать доступ и удалять дополнения нужно в панели. Если не выбрать протокол при повторном запуске, уже установленный протокол не удалится.

Изменения VPS и панели не образуют общую транзакцию: при сетевой ошибке часть шагов может успеть выполниться. Повторный запуск сверяется с текущим состоянием, а не повторяет создание объектов вслепую. Не запускайте два установщика одновременно и не редактируйте профиль во время применения. Мастер сверяет профиль непосредственно перед PATCH, но не может полностью исключить одновременную запись другого администратора.

### Тахион на OpenWrt

В некоторых версиях Тахиона автоматический выбор исходящего интерфейса мешает соединению с Yggdrasil. Тогда на стороне роутера нужна привязка `bind_interface: "yggdrasil"` или соответствующая постоянная настройка Тахиона. Обычная VLESS-ссылка и стандартная подписка это поле не передают.

**Этот установщик не исправляет выбор интерфейса в Тахионе.** Настройки сервера, inbound и сквадов работают независимо от этой особенности клиента; скрипт на VPS не может задать сетевой интерфейс чужого роутера.

## Проверка и автоматический запуск

Проверить доступ к API и план без применения настроек:

```bash
bash /tmp/remna-ygg-install.sh --check
```

Загрузчик при необходимости установит Python/curl, но `--check` не применяет профиль и firewall.

Повторно показать результат последнего запуска:

```bash
remnawave-yggdrasil --result
```

`--result` читает сохранённый результат, а не запрашивает текущее состояние панели.

Для автоматизации доступны `--panel`, `--node UUID`, `--source-host UUID`, повторяемые `--protocol hy2|grpc|xhttp|ygg`, `--squad UUID`, `--access-mode subscription|restricted`, `--allow-ip`, `--ssh-allow-ip`, а также `--no-ssh`/`--ssh`, `--cert`, `--key`, `--peer` и `--ygg-port`. При `--yes` нода и исходный Host должны определяться однозначно. `--allow-ip` подразумевает режим `restricted`; сочетание с `--access-mode subscription` отклоняется. В режиме `subscription` флаг `--ssh` требует отдельный `--ssh-allow-ip` или сохранённый SSH-список. Ограничения старого подключения 0.1.x на прежнем порту сохраняются независимо.

Токен передаётся через `--token-file` или переменную `REMNAWAVE_API_TOKEN`; секретная ссылка/Cookie панели — через `--access-file` или `REMNAWAVE_PANEL_ACCESS`. Файлам нужен режим `600`. Секреты в аргументах командной строки не принимаются и не сохраняются.

## Изменения на VPS

- **Yggdrasil**, только если выбран: официальный пакет 0.5.14 для amd64/arm64 с проверкой SHA256. Идентичность уже установленного Yggdrasil 0.5.x сохраняется. IPv6 включается только на loopback и TUN Yggdrasil; WAN, default route и DNS не перенастраиваются.
- **Сетевой доступ.** Отдельный Yggdrasil inbound слушает IPv6 wildcard на выделенном порту, чтобы запуск Xray не зависел от готовности TUN. Правила nftables закрывают этот порт на всех внешних адресах, кроме собственного адреса Yggdrasil, и допускают только разрешённых клиентов. Публичные gRPC/XHTTP/Hysteria2 открываются точечно в активном UFW; сам UFW автоматически не включается. При нестандартном INPUT firewall разрешения нужно подготовить вручную и подтвердить через `--firewall-ready`.
- **Новый сертификат Hysteria2.** Используются отдельные `/dev/shm/remna-ygg-hy2-cert.pem` и `/dev/shm/remna-ygg-hy2-key.pem`; ключ получает режим `600`. Таймер восстанавливает файлы после загрузки и проверяет изменения раз в час. При изменении файлов перезапускается только локальный контейнер Remnanode, что кратко затрагивает все протоколы этой VPS. Чужие файлы `/dev/shm/hysteria_*.pem` не заменяются. У переиспользуемого стороннего Hysteria2 сохраняется его механизм сертификатов. Наши старые общие пути автоматически мигрируют только в отдельном профиле; в общем профиле сохраняются, чтобы не нарушить работу соседних нод.
- **Резервные копии.** JSON профиля и план сохраняются в `/etc/remnawave-yggdrasil/backups/`, доступном только root. API-токен и секретная ссылка туда не записываются.
- **Существующая установка.** Docker Compose, Docker NAT/FORWARD и публичный SSH не переписываются. Задачи cron сторонних скриптов сохраняются: если они настроены на ежедневный перезапуск ноды, он продолжится.

В режиме 0.1.x создавался дополнительный Host на прежнем inbound. Он не удаляется автоматически, его ограничения сохраняются. После проверки нового отдельного inbound старый Host можно отключить в панели. [Инструкция для 0.1.x](docs/legacy-v0.1.md).

## Необязательный конвертер для ручной работы

**Для обычной установки он не нужен: мастер сам меняет профиль через API.** Конвертер оставлен для тех, кто хочет подготовить JSON локально и применить его вручную.

[RemnawaveConverter.exe из выпуска v0.2.1](https://github.com/BrainDeLook/remnawave-yggdrasil/releases/tag/v0.2.1) работает на Windows x64 без Python, сайта и подключения к сети. Новые обычные релизы установщика не включают EXE. Откройте экспортированный JSON профиля, выберите исходный TCP Reality inbound и дополнения, затем сохраните результат **в новый файл**. При ручном применении зависимости на VPS, активные inbound ноды, Host и права сквадов нужно настроить отдельно.

Конвертер сохраняет исходные inbound, DNS и параметры Reality (`dest`/`target`, `xver`, ключи, SNI). Новые inbound добавляются в `inboundTag` правил исходного TCP; существующие gRPC/XHTTP/Hysteria2 переиспользуются с их прежними правилами. Vision не переносится в новые gRPC/XHTTP. Конфликт порта или tag вызывает ошибку; снятие галочки означает «не добавлять», а не «удалить». Готовый JSON содержит приватные ключи — не публикуйте его.

Запуск исходников: `python desktop.py` (нужен Python с Tk). Вариант для командной строки:

```bash
python converter.py source.json result.json --base node-vless-443 --protocol ygg
```

## Проверки

Unit-тесты проверяют API, преобразование профиля, маршрутизацию, сертификаты и миграцию имён. Полный CI на Ubuntu использует настоящие Remnawave Panel, три Node и Yggdrasil: проверяет HTTPS через все транспорты, соседнюю ноду с общим профилем и ноду с отдельным профилем, исходные Host/сквады/контейнеры, сетевые ограничения, сертификаты и повторный запуск. Отдельный Windows workflow для сборки и проверки EXE запускается вручную. Для arm64 закреплены официальные бинарники; полный runtime CI выполняется на amd64.
