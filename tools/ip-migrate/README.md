# Смена IP VPS с панелью Remnawave

Отдельный скрипт для панели, установленной через **eGames**. Помогает восстановить связь с нодами после смены публичного IPv4 **у той же VPS**. Панель, базу и ноды переносить или переустанавливать не требуется.

## Когда запускать

1. Поменяйте IP VPS в кабинете хостинга и убедитесь, что вход по SSH работает по новому адресу.
2. Самостоятельно обновите нужные DNS-записи Cloudflare, сохранив прежние домены панели и подписок.
3. Запустите скрипт **на VPS панели**, от `root`:

```bash
curl -fsSL https://raw.githubusercontent.com/BrainDeLook/remnawave-yggdrasil/main/tools/ip-migrate/install.sh -o /tmp/remna-ip-migrate.sh && bash /tmp/remna-ip-migrate.sh
```

Обычно достаточно ввести **новый IPv4**. Скрипт проверит, что адрес назначен этой VPS, покажет найденные ноды и план, затем запросит подтверждение. Пример адреса: `203.0.113.25`; вводите свой реальный новый IP.

## Что изменится

- На удалённых нодах с активным UFW появится разрешение для нового IP панели к **TCP-порту управления нодой** — обычно `2222`.
- Старые правила сохранятся. Сам UFW скрипт не устанавливает и не включает.
- Если указан старый IP, скрипт также заменит его в полях адреса **Nodes** и **Hosts**, только когда значение целиком совпадает со старым IP. Домены и внутренние адреса сохранятся.

DNS, сетевые настройки ОС, профили Xray, пользователи, сквады, ключи и сертификаты не меняются. Локальная нода с внутренним адресом вроде `172.30.0.1` сохраняется.

После применения скрипт наблюдает состояние нод и доступность их портов **не менее 45 секунд**, чтобы не принять старый статус панели за успешное переподключение. Последний успешно применённый IP сохраняется в `/var/lib/remnawave-ip-migrate/state.json`: при следующей смене он используется как предыдущий адрес.

До изменений сохраняются план и прежние адреса в `/var/backups/remnawave-ip-migrate/` на VPS панели. Перед добавлением разрешения на соответствующей ноде отдельно сохраняется снимок UFW внутри `/var/backups/remnawave-ip-migrate/`. Точные пути показываются в выводе; файлы доступны только root. При `--plan` резервные копии и состояние переноса не создаются.

## Откуда берётся доступ к нодам

Используются уже настроенные SSH-подключения eGames из `/usr/local/remnawave_reverse/remote-exec/`, их ключи и сохранённые ключи серверов `known_hosts`. Нода сопоставляется со своим SSH-подключением по адресу; неоднозначное совпадение не выбирается автоматически.

Если нода недоступна, а необходимого SSH-подключения или ключа нет, предварительная проверка остановит применение. Сначала настройте SSH-доступ к этой ноде в eGames и повторите запуск. Проверка также остановится при несовпадении сохранённого ключа сервера. Уже доступную ноду без сохранённого SSH скрипт оставит без изменений и включит в итоговую проверку. Пароли скрипт не подбирает и новые SSH-ключи на ноды не устанавливает.

Для обычного обновления правил UFW API-токен не нужен: список нод читается из локальной базы. Для замены явных адресов Nodes/Hosts используется сохранённый токен eGames; если подходящего токена нет, появится скрытый запрос. Нужны права чтения и изменения **Nodes** и **Hosts**. Токен страницы подписок может не иметь этих прав.

Управление нодой через дополнительный SOCKS-прокси этим скриптом не поддерживается: в таком соединении исходящий IP может принадлежать прокси, а не VPS панели. Если такой режим найден, скрипт остановится до применения.

## Параметры

Сначала скачайте загрузчик командой выше. Все параметры передаются после имени файла:

| Параметр | Действие |
|---|---|
| `--new-ip АДРЕС` | Задать новый IPv4 без вопроса |
| `--old-ip АДРЕС` | Указать предыдущий IPv4 для точечной замены адресов Nodes/Hosts |
| `--plan` | Только проверить и показать план, без применения |
| `--yes` | Применить прошедший проверки план без дополнительного подтверждения |
| `--timeout СЕКУНДЫ` | Время ожидания связи: от 45 до 900 секунд, по умолчанию 90 |

Проверка перед применением:

```bash
bash /tmp/remna-ip-migrate.sh --new-ip НОВЫЙ_IP --plan
```

Первый запуск с заменой старого IP, если он записан в панели напрямую:

```bash
bash /tmp/remna-ip-migrate.sh --new-ip НОВЫЙ_IP --old-ip СТАРЫЙ_IP
```

Замените `НОВЫЙ_IP` и `СТАРЫЙ_IP` реальными адресами. Если ноды и Host используют домены или внутренние адреса, `--old-ip` для них не требуется.

## Если проверка не прошла

| Сообщение или ситуация | Что сделать |
|---|---|
| Новый IP не назначен VPS | Проверьте смену адреса у хостинга и сетевую конфигурацию VPS |
| Нет подходящего SSH-подключения | Настройте доступ к соответствующей ноде через eGames |
| Ключ сервера не совпадает с `known_hosts` | Проверьте причину и настоящий ключ ноды; не отключайте проверку ключей |
| API отказал в доступе | Используйте токен с правами Nodes/Hosts; остальные разрешения не нужны |
| Нода осталась без связи | Проверьте firewall хостинга, порт и состояние Remnanode; разрешения UFW недостаточно для внешнего firewall |

Это инструмент для описанной установки eGames, а не универсальная миграция произвольного сервера. При ошибке во время применения часть разрешений уже могла добавиться; старые правила при этом сохраняются. Исправьте указанную причину и повторите запуск.
